GYMDESK
Gym Management SaaS — Initial Project Setup & Structure
Subscription-based multi-tenant product · MERN Stack · v1.0 Planning Document
1. Product Summary
GymDesk is a subscription SaaS for gym owners. It has two layers: a Root Admin layer (your own company/team, controlling the whole platform) and a Subscriber layer (each paying gym, which itself has three internal logins — Admin/Owner, Trainer, Member). This document defines the tech stack, the role hierarchy, the module list per role, and the initial folder structure to start development.

3. Public Website & Onboarding Flow
This is the front door — the journey a brand-new gym owner (e.g. 'Arun') goes through before any Admin panel exists for him. Everything else in this document assumes a subscriber already exists; this flow is what actually creates one.
#
Page
What Happens
1
Landing Page
Public marketing site — product info, feature highlights, testimonials, pricing. No login required.
2
Sign Up / Sign In
Arun creates an account (name, gym name, phone/email, password) or signs back into an existing one.
3
Plan Selection
Arun picks a plan — Free (7-day trial) or a paid tier (Starter/Basic/Premium).
4
Free Trial Activation
If Free is chosen: a subscriber record is created with plan='free', trialEndsAt = now + 7 days, isActive=true — full Admin panel unlocks immediately, no payment needed.
5
Payment (paid plans)
Razorpay checkout. On success: subscriber.plan is set, isActive=true, planStartedAt recorded.
6
Admin Panel Unlocked
Arun is redirected to /admin/dashboard, now logged in as Admin for his own gym — ready to add Trainers and Members.
7
Trial Expiry / Renewal
A daily cron job checks trialEndsAt / plan expiry. If expired with no payment, Arun's panel access is restricted to a 'Renew Plan' screen only — his data is preserved, not deleted.
ℹ Paid features stay locked behind step 4/5 — the Admin panel simply doesn't unlock (or reverts to a renew-only screen) until a subscriber has an active trial or active paid plan. This is a plan-status check, not a separate codebase.

5. Tenant Data Isolation (Critical)
Every gym's data must be completely walled off from every other gym's. If Arun logs in as Admin, he only ever sees his own Trainers and Members — never another gym owner's. The same isolation applies down the chain to Trainer and Member logins. This is enforced at the database/API layer, not just hidden in the UI:
Every gym gets a unique subscriberId the moment it's created in the onboarding flow above.
Every record created afterward — every Trainer, Member, Attendance entry, Payment — is stamped with that subscriberId.
Every login's JWT carries their subscriberId (Root Admin is the one exception — it has none, since it spans all gyms).
One shared middleware (tenantScope.js) reads subscriberId off the JWT and injects it into every database query automatically — so no individual route can forget to filter by it.
Result: two gyms can have identically named members, trainers, whatever — there is zero chance of data crossing between them.

11. Recommended Build Order
Phase 0 — Public onboarding: Landing page, Sign Up/Sign In, Plan Selection, free-trial activation, Razorpay payment for paid plans. This is what creates a subscriber in the first place.
Phase 1 — Auth, tenantScope & role guard: 4 logins (Root Admin, Admin, Trainer, Member) working with JWT + subscriberId-based data isolation + route protection.
Phase 2 — Root Admin: Dashboard, Subscriber list, Plan Creation, Settings (core platform control first).
Phase 3 — Admin (gym owner): Members, Attendance, Payment, Payment History (the daily-use core).
Phase 4 — Admin continued: Trainers, Earnings, PT Sessions, Workouts, Trial, Accounts, gym-level Plan Creation.
Phase 5 — Trainer & Member logins (mostly reuse of Admin's data with restricted views).
Phase 6 — Root Admin: Coupons, Analytics, Request Access.
Phase 7 — AI Plans module (can be gated behind a premium plan later, same as the earlier draft).
Phase 8 — Trial-expiry cron + plan-guard: lock an expired subscriber to a 'Renew Plan' screen without deleting their data.
